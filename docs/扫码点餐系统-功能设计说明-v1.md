# 扫码点餐系统｜功能设计说明 v1

> 版本：v1（最小可用版｜局域网打印）
> 定位：本文档是**功能设计说明**，在《功能清单》之上回答"每个功能怎么用、规则是什么、边界怎么处理"，不涉及代码与技术实现细节。
> 配套文档：《功能清单》（做什么）、《顾客 H5 原型 / admin 管理端原型》（长什么样）、《数据库设计》（存什么）。
> 约束继承：仅堂食扫码点餐、线下前台结算、无线上支付、无外卖、局域网 ESC/POS 直连打印。

---

## 一、系统总览

### 1.1 角色与端

| 角色 | 使用端 | 核心职责 |
|---|---|---|
| 顾客 | 顾客 H5（微信扫码免登录） | 选菜、加料、备注、提交订单、查看自己的订单 |
| 收银员 | admin 合并端（收银台） | 桌台订单处理、改单/退菜/挂单、收款结算、打印 |
| 管理员 | admin 合并端（后台 + 收银台） | 全部收银能力 + 菜品/桌台/打印/账号/权限/报表/日志管理 |

- admin 前端是**一个项目**：登录后按角色展示不同菜单；收银员默认只见收银台，管理员见全量菜单（含收银台）。
- 前端菜单可见性只是体验层过滤，**接口层鉴权为最终防线**。

### 1.2 业务闭环

```
顾客扫码点单 → 生成【待结算】订单 → 自动打印后厨小票
→ 后厨凭小票制作、喊桌上菜（系统不跟踪）
→ 顾客到前台结账 → 收银员核对/改单/退菜（可选）
→ 线下收款确认 → 点击结算 → 订单【已结清】→ 自动打印结账单
→ 管理员查看流水/报表/日志，维护基础数据
```

### 1.3 订单状态机（唯一主线）

| 状态 | 含义 | 可流转到 |
|---|---|---|
| 待结算 pending | 已下单未收款 | 已结清 / 已取消 / 挂单暂存 |
| 挂单 hold | 收银主动暂存（不清桌） | 待结算（恢复） |
| 已结清 paid | 收款完成，终态 | — |
| 已取消 cancel | 整单作废，终态 | — |

规则：
- 改单、退菜、加菜只能发生在**待结算/挂单**状态；已结清、已取消订单只读。
- 结算只允许从"待结算"触发（挂单需先恢复）。
- 状态变更全部写入操作日志。

## 二、全局设计规则

### 2.1 金额与计价

- 所有金额保留 2 位小数，界面简显时可省略 `.00`。
- **单品价格 = 菜品基础价 + 所选规格差价之和**（如 招牌水煮牛肉 42 元 + 大份 +3 = 45 元）。
- **明细小计 = 单价 × 数量**；**订单合计 = Σ 未退菜品明细小计**；退菜后合计随之变化。
- 加料价计入对应明细行的单价（设计口径：加料随菜计价，不单独成行金额展示，但保留加料明细）。
- **抹零**：全局开关（系统设置），开启后结算时对合计做角位抹零（抹去分位以下），抹零金额在结账单与详情中体现；关闭则按原价结算。
- 单位统一为元（¥），数据库层用 DECIMAL(10,2)，禁止浮点运算误差传导到对账。

### 2.2 快照冗余原则

订单在创建/改单时**快照**菜品名称、单价、规格文本、加料文本到订单明细。后续菜品改价、改规格、删菜品，不影响历史订单与已打小票——保证对账与小票一致。

### 2.3 时间与筛选口径

- 全系统统一"自然日"口径（营业日=自然日，最小版不做过零点跨日拆分）。
- 列表筛选统一三档：**今日 / 近 7 日 / 自定义区间**（自定义起止可倒序自动交换）。
- 报表"近 7 日营收趋势"支持独立切换 7 日/30 日窗口，不随页面级口径联动（跨期指标单独控制）。

### 2.4 留痕原则

所有**影响业务数据的操作**必须写操作日志：登录、订单全生命周期操作（改单/挂单/恢复/退菜/取消/结算）、打印操作（重打）、配置变更（打印机/模板/菜品/加料/账号/权限/系统设置）。日志含操作时间、操作人、类型、对象、详情、来源 IP。

### 2.5 列表通用交互规范

所有列表页遵循同一套模式（降低学习成本、减少实现分叉）：

- **筛选栏**：关键词输入（回车/输入触发）+ 下拉维度 + 时间段 + 计数摘要 + 重置按钮；任何筛选变化自动回到第 1 页。
- **分页**：统一分页组件，页码窗口式展示；筛选条件签名变化即重置页码。
- **弹窗**：所有确认/输入/详情一律使用自绘弹窗（互斥显示），禁用浏览器原生弹窗；危险操作（删除、整单取消）用红色确认按钮 + 后果说明文案。
- **空态**：筛选无结果统一显示"无符合条件的记录"空态提示。

## 三、顾客 H5 端设计

### 3.1 入座流程（锁定桌号）

1. 扫描桌台二维码 → 打开 H5，URL 携带桌号（二维码内容绑定 tableId）。
2. 入座页展示：门店名称、欢迎语、**当前桌号**、就餐人数选择（1–12 档）、"开始点餐"按钮。
3. 桌号由二维码锁定，**顾客端不可手动修改**（防跨桌点单、防传错桌号）；贴错码/换桌由服务员引导重新扫码或收银端调整。
4. 就餐人数写入订单，供收银端展示与客单价统计。

### 3.2 点餐页

**结构**：顶部门店条（名称+桌号）、左侧分类导航（后台配置顺序）、右侧菜品卡片列表、底部购物车栏。

- 菜品卡片：图片、名称、售价（起价）、售罄标识置灰不可点。
- **搜索**：独立搜索页，按名称/分类关键词跨分类检索，实时结果，空关键词恢复全量。
- 分类切换联动右侧滚动定位；右侧滚动反向高亮左侧分类。

**规格与加料（计价核心）**：

- 点"选规格"类菜品先弹规格选择弹窗：逐组必选一个选项，选项差价实时联动底部单价（如 大份 +3 → 显示 45 元）。
- 无规格菜品直接加入购物车（默认规格）。
- 加料：在规格弹窗内（或加料面板）选择，**每项加料有限选上限 N 份（N=0 表示不限）**，步进器到上限后禁止继续加；仅可勾选绑定到该菜品的加料项。
- 加入购物车时生成明细快照文本："大份/微辣 · 加宽粉"。

### 3.3 购物车与提交

- 底部栏：合计金额 + 购物车图标（角标数量）→ 展开购物车抽屉。
- 抽屉内：按菜品分组，可增减数量、删除、修改规格（重新弹规格选择替换当前明细）。
- 整单备注输入（少辣、不要葱等），随订单提交。
- 提交校验：
  - 购物车为空 → 禁止提交；
  - 售罄菜品在购物车中 → 提交时拦截并提示移除；
  - 营业时间外可浏览但提交给出提示（最小版：提示不硬拦截，由门店运营决定）。
- 提交成功：自绘成功弹窗展示订单号，提示"请前往前台结账"；清空购物车。
- 提交后订单进入"待结算"，触发后厨小票打印。

### 3.4 我的订单

- 列表：本人提交的订单（按桌号维度），展示订单号、时间、状态、金额。
- 详情：菜品明细（含规格/加料文本、**退菜标记**）、备注、合计。
- 无顾客自主取消入口（取消统一收银处理）。

## 四、admin 合并端设计

### 4.1 登录与权限

- 登录页：账号 + 密码，分栏布局；登录失败统一错误提示（不泄露账号存在性）。
- 登录成功：按角色取默认首页——管理员进桌台概览（收银台），收银员进收银台。
- **角色菜单权限**：系统设置内可按角色勾选可见菜单；收银员改动即时生效（侧边栏重建 + 页面访问拦截，无权限访问直接重定向回收银台）；管理员固定全量、不可修改。
- 顶部角色切换器（演示用）退出登录、修改密码入口预留。

### 4.2 收银台（核心工作页）

**桌台概览**：

- 按区域分组展示桌台卡片，三色状态：空闲（灰）/ 待结算（有未结订单，橙）/ 挂单（蓝）；卡片显示桌号、人数、金额、单量摘要。
- 点击桌台进入该桌订单操作区；支持按区域/状态过滤定位。

**订单操作区（对"待结算/挂单"订单）**：

| 操作 | 规则 |
|---|---|
| 改单（加菜/改数量/改规格） | 弹出点餐面板，复用顾客端菜品/规格/加料逻辑；保存后合计实时重算，**自动重打后厨小票**并记日志 |
| 单品退菜 | 勾选明细退菜，必选/可选退菜原因（弹窗输入）；退菜后合计重算，明细打"已退"标记；已退菜品不可再退 |
| 整单取消 | 红色二次确认（显示桌号/件数/金额），订单转"已取消"，桌台释放 |
| 挂单 | 订单转"挂单"暂存，桌台保持占用，可从挂单列表恢复 |
| 恢复 | 挂单 → 待结算 |
| 结算 | 选择支付方式（现金 / 微信静态码 / 支付宝静态码 / 其他）→ 显示应收（含抹零）→ 收银员**线下确认收款后**手动点击"确认结算"→ 订单转"已结清"，自动打印结账单 |

**结算台内嵌**：当日订单总数、今日营收、支付方式分布的简易摘要卡。

**关键口径**：系统**不校验支付结果**，收款真实性由收银员线下确认；结算金额记录实收（含支付方式）用于对账。

### 4.3 菜品管理

- **左右分栏**：左侧分类列表（新增/编辑/删除/上移下移排序、各类菜品数），右侧菜品表格（搜索框按名称关键词过滤）。
- 菜品表单（弹窗）：名称、售价、分类、排序、图片（预留上传）、售罄开关。
- **规格组编辑器**：菜品可挂多组规格（如 份量、辣度），每组多选项，**选项可设差价**（正数加价）；差价在顾客端计价与收银端改单同步生效。
- **加料管理**：独立模态框列表（不占主页面），字段：名称、加价金额、限选数量（0=不限）、绑定菜品（多选）；绑定关系决定顾客端可选项。
- 删除菜品：二次确认；仅影响后续点单，历史订单因快照不受影响。
- 售罄为可逆开关，非删除。

### 4.4 桌台管理

- **区域管理**：区域增删改（弹窗），桌台必须归属区域。
- 桌台列表：桌号、所属区域；增删改均带确认。
- **二维码**：批量生成全桌二维码（预览+下载）；单桌"二维码"按钮查看该桌专属二维码（弹窗展示+复制链接），与批量入口区分，避免误生成全部。
- 桌台状态可视化与收银台一致（空闲/待结算/挂单），此处为管理视角。

### 4.5 订单流水

- 筛选：订单号关键词 + 时间段（今日/近7日/自定义区间）+ 桌号 + 结算状态；摘要显示"条数 + 合计金额"。
- 行操作"详情"：弹窗展示完整订单（明细含退菜标记、备注、支付方式、实收）。
- **导出 Excel**：按当前筛选结果导出（对账用），导出前提示覆盖范围。

### 4.6 打印配置（Tab 三区）

1. **打印机**：列表（名称、IP:端口、用途、在线状态）；新增/编辑/删除/测试；测试打印向 `ip:9100` 发指令并回写连通结果（成功/超时原因）；同一用途建议仅设一台默认。
2. **小票模板**：后厨小票、结账单两个 ESC/POS 模板编辑器；占位变量支持桌号、单号、菜品明细、备注、金额、时间等；保存后**下次打印生效**（不重打历史）。
3. **打印日志**：筛选（订单号/单据类型/打印机/状态）+ 计数；行操作：详情（含 IP:端口、失败原因）、重打/重试、删除（二次确认，仅清日志不动订单）。失败记录醒目标红。

**打印触发时机**：顾客下单 → 后厨小票；改单加菜 → 后厨小票重打；结算 → 顾客结账单；手动重打/重试 → 对应单据。

### 4.7 轻量报表（商家视角）

- **页面级口径条**：今日 / 近 7 日（影响除趋势外的所有卡片）。
- 核心卡片：
  - 经营总览：营收、订单数、客单价、环比昨日期增减；
  - 营收趋势：柱状图（独立 7 日/30 日窗口，多柱紧凑模式仅标关键数值）；
  - 菜品销量排行 TOP5（主食类不计入排行，口径可解释）；
  - 支付方式构成（笔数+金额，对账用）；
  - 退菜统计（次数+金额+原因分布）；
  - 滞销提醒（低销量菜品，辅助下架决策）。
- 设计原则：每张卡回答一个商家决策问题，不做大而全 BI。

### 4.8 系统设置

- 门店信息：门店名称、小票抬头、营业时间（展示于顾客端）、联系电话。
- 抹零开关（全局，实时影响结算）。
- 账号管理：新增账号（角色二选一）、启用/禁用（禁用即不可登录）、角色调整（提示重新登录生效）。
- **角色菜单权限**：按角色勾选侧边栏菜单；保存即生效；附"恢复默认（收银员仅见收银台）"。

### 4.9 操作日志

- **留痕范围**（16 类）：登录、改单、挂单、恢复、整单取消、退菜、结算、手动重打、打印机新增/编辑/删除/测试、模板修改、菜品新增/编辑/删除、账号新增/启禁/角色调整、权限修改/重置、系统设置变更。
- 字段：时间、操作人、操作类型（彩色标签）、操作对象、详情、来源 IP、日志编号。
- 筛选：时间段（今日/近7日/自定义区间）+ 关键词（对象/详情）+ 操作类型 + 操作人，带计数摘要与分页。
- 行操作：**详情**（弹窗全字段展示）、**删除**（红色二次确认，提示不可恢复、建议优先归档；仅清留痕不动业务数据）。
- 访问：仅管理员菜单可见，接口层同权限校验。

## 五、异常与边界场景清单

| # | 场景 | 设计处理 |
|---|---|---|
| 1 | 顾客扫错桌/换桌 | 桌号不可手动改，服务员引导重扫或收银端改单调整 |
| 2 | 下单后菜品售罄/改价 | 历史订单快照不变；新点单按新数据；改单加菜时以当前数据快照 |
| 3 | 打印机离线/超时 | 打印日志记"失败+原因"；收银端提示；通过日志"重试"补打，不阻塞订单流程 |
| 4 | 结算时顾客要求去掉某菜 | 走单品退菜后再结算，合计自动重算 |
| 5 | 已结清订单发现漏菜 | 最小版不支持对已结清订单改单；线下处理（赠菜等），留待 v2 |
| 6 | 收银员误点整单取消 | 二次确认 + 操作日志留痕（操作人可追责） |
| 7 | 挂单后顾客直接买单 | 恢复挂单 → 待结算 → 正常结算 |
| 8 | 顾客提交时菜品刚被删除 | 后端校验菜品有效性，失败明细返回提示重新选择 |
| 9 | 并发点单（同桌多人扫） | 同桌订单按桌号合并到收银端桌台卡片（多单并列展示，逐单结算） |
| 10 | 加料限选超限 | 步进器到上限禁用，后端二次校验 |
| 11 | 规格差价改错导致负价 | 表单层校验差价 ≥ 0，售价 ≥ 0 |
| 12 | 账号被禁用时在线 | Token 校验失败强制退出 |

## 六、非功能设计要求

- **性能**：列表默认分页（收银桌台全景一屏内）；打印为异步短连接，不阻塞收银操作。
- **兼容**：顾客 H5 以微信内置浏览器（移动端）为主要目标；admin 端以桌面 Chrome/Edge 为主，收银 H5 页兼容平板横屏。
- **安全**：密码哈希存储；接口级角色鉴权；操作日志记录来源 IP；二维码链接仅含桌号标识，不含敏感信息。
- **可运维**：打印机静态 IP 绑定；打印失败可自助重试；日志支持按时间归档清理（防无限膨胀）。
- **部署**：后端部署于店内常开内网主机，与打印机同网段；顾客 H5 通过局域网/映射访问。
